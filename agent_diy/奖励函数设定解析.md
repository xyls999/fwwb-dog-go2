# Go2 RL Gym 奖励函数设定解析

本文档根据项目源码整理强化学习奖励设计，重点覆盖每个 `_reward_*` 函数的计算方式、训练作用，以及它和其他奖励项之间的关系。

主要代码位置：

- 环境奖励汇总：`legged_gym/envs/base/legged_robot.py`
- 基础奖励默认配置：`legged_gym/envs/base/legged_robot_config.py`
- Go2 默认注册任务配置：`legged_gym/envs/go2/go2_config.py`
- Go2 专属奖励扩展：`legged_gym/envs/go2/go2_env.py`
- 任务注册：`legged_gym/envs/__init__.py`

## 1. 奖励总体机制

### 1.1 调用链

训练脚本 `legged_gym/scripts/train.py` 创建环境后，在每次 `env.step(actions)` 中进入：

1. `LeggedRobot.step`
2. `LeggedRobot.post_physics_step`
3. `check_termination`
4. `compute_reward`
5. `compute_observations`

PPO、CTS、MoE-CTS 等算法侧并不重新定义奖励函数。它们只接收环境返回的标量 `rewards`，再写入 rollout storage。也就是说，本项目的奖励设计集中在环境层。

### 1.2 自动发现奖励函数

`_prepare_reward_function` 会读取 `cfg.rewards.scales` 中所有非零项，并寻找同名函数：

```text
reward name: tracking_lin_vel
function:    self._reward_tracking_lin_vel()
```

特殊点：

- scale 为 `0` 的奖励会被删除，不参与计算。
- 非零 scale 会先乘以环境时间步长 `dt`。
- 本项目 Go2 默认控制配置为 `sim.dt = 0.005`、`decimation = 4`，所以 `dt = 0.02`。
- `termination` 不在普通循环里算，而是在 `only_positive_rewards` 裁剪之后单独追加。
- 当前 Go2 默认配置 `only_positive_rewards = False`，因此总奖励允许为负。

### 1.3 当前注册任务实际使用的奖励配置

`legged_gym/envs/__init__.py` 中注册的 `go2`、`go2_cts`、`go2_moe_cts`、`go2_moe_ng_cts`、`go2_mcp_cts`、`go2_ac_moe_cts`、`go2_dual_moe_cts` 都使用 `legged_gym/envs/go2/go2_config.py` 里的 `GO2Cfg()` 作为环境配置。

因此，默认训练实际启用的奖励项如下：

| 奖励名 | 配置系数 | 乘 `dt=0.02` 后 | 额外课程系数 |
| --- | ---: | ---: | --- |
| `tracking_lin_vel` | `1.0` | `0.02` | 无 |
| `tracking_ang_vel` | `0.5` | `0.01` | 无 |
| `lin_vel_z` | `-2.0` | `-0.04` | `1.0 -> 0.0`，0 到 1500 iter |
| `ang_vel_xy` | `-0.05` | `-0.001` | 无 |
| `dof_acc` | `-2.5e-7` | `-5e-9` | 无 |
| `dof_power` | `-2e-5` | `-4e-7` | 无 |
| `torques` | `-1e-4` | `-2e-6` | 无 |
| `correct_base_height` | `-1.0` | `-0.02` | `1.0 -> 10.0`，0 到 5000 iter |
| `action_rate` | `-0.01` | `-0.0002` | 无 |
| `action_smoothness` | `-0.01` | `-0.0002` | 无 |
| `collision` | `-1.0` | `-0.02` | 无 |
| `dof_pos_limits` | `-2.0` | `-0.04` | 无 |
| `feet_regulation` | `-0.05` | `-0.001` | 无 |
| `hip_to_default` | `-0.05` | `-0.001` | 无 |

Go2 默认参数：

- `base_height_target = 0.38`
- `soft_dof_pos_limit = 0.9`
- `tracking_sigma = 0.25`
- `dynamic_sigma` 启用
- `max_contact_force = 147`
- `min_legs_distance = 0.1`
- `turn_over = False`，所以 `turn_over_scales.upright` 默认不生效

## 2. 课程奖励与动态追踪宽容度

### 2.1 Reward Curriculum

`update_reward_curriculum` 每个 PPO/CTS 采样周期更新一次课程系数，系数按训练 iteration 线性插值。

当前 Go2 默认只有两项：

```python
lin_vel_z:            1.0 -> 0.0,  0 到 1500 iter
correct_base_height:  1.0 -> 10.0, 0 到 5000 iter
```

作用：

- 前期强惩罚机身竖直速度，帮助快速获得稳定站立和基础步态。
- 后期逐渐放松 `lin_vel_z`，避免爬台阶、越障、波浪地形时过度压制必要的上下起伏。
- `correct_base_height` 后期加重，抵消复杂动作中机身趴低、滑倒、重心偏移的问题。

这两个课程项形成一个明显的训练节奏：先压住不稳定竖直运动，再逐渐把重点转到保持合理机身高度。

### 2.2 Dynamic Sigma

`tracking_lin_vel` 和 `tracking_ang_vel` 使用指数奖励：

```text
reward = exp(-error^2 / sigma)
```

`sigma` 越大，速度误差受到的惩罚越宽松；`sigma` 越小，追踪要求越严格。

默认 `tracking_sigma = 0.25`。启用 `dynamic_sigma` 后，`sigma` 会随三类因素变化：

1. 指令速度绝对值越大，越接近各地形的 `max_sigma`。
2. 地形越难，`terrain_level` 越高，越接近动态 sigma。
3. 平地、斜坡等部分地形的 `max_sigma` 仍是 `0.25`，保持严格追踪；波浪、楼梯、障碍、落脚石、gap 等地形会更宽松。

这表示项目并不是一味要求复杂地形高速精准追踪，而是允许策略在困难地形上用一部分速度误差换稳定性和通过率。

## 3. 逐项奖励函数

### 3.1 `_reward_tracking_lin_vel`

方式：

```text
error_xy = (command_xy - base_lin_vel_xy)^2
reward = exp(-(error_x / sigma_x + error_y / sigma_y))
```

其中 `base_lin_vel` 是机身坐标系下的线速度，`commands[:, :2]` 是目标 x/y 速度。若 `dynamic_sigma` 启用，`sigma_x` 和 `sigma_y` 会按地形、速度、地形等级动态调整。

作用：

- 主任务奖励，驱动机器人按用户指令前进、后退、横移。
- 是整个 locomotion 目标的核心正奖励。

关系：

- 与 `tracking_ang_vel` 一起定义“听指令”的能力。
- 与 `feet_air_time`、`feet_regulation`、`correct_base_height` 存在张力：速度追踪可能诱导大步幅、高抬腿或压低机身，后几项负责约束步态质量。
- 与 `dof_power`、`torques`、`dof_acc` 存在效率约束关系：不能靠暴力力矩追踪速度。
- `dynamic_sigma` 会在困难地形放松它，给稳定性奖励和惩罚项留下优化空间。

### 3.2 `_reward_tracking_ang_vel`

方式：

```text
error_yaw = (command_yaw - base_ang_vel_z)^2
reward = exp(-error_yaw / sigma)
```

作用：

- 鼓励机器人跟踪目标偏航角速度，实现转向控制。

关系：

- 与 `tracking_lin_vel` 共同组成速度命令追踪。
- 与 `ang_vel_xy` 区分：本项奖励 yaw 轴角速度跟踪，`ang_vel_xy` 惩罚 roll/pitch 方向的角速度。
- 与 `hip_to_default`、`action_smoothness` 有间接冲突：快速转向可能需要髋关节偏离默认位姿或动作快速变化，正则项限制其过度使用。

### 3.3 `_reward_lin_vel_z`

方式：

```text
penalty = base_lin_vel_z^2
```

当前系数为负，且课程系数从 `1.0` 线性降到 `0.0`。

作用：

- 惩罚机身竖直方向速度，减少跳动、弹跳和仿真早期的不稳定上下震荡。

关系：

- 与 `correct_base_height` 共同约束机身竖直状态：前者约束速度，后者约束位置。
- 与复杂地形通过能力存在冲突，所以后期课程把它降到 0。否则上楼梯、越障时必要的 z 向运动会被过度压制。
- 与 `feet_regulation` 互补：`feet_regulation` 管脚，`lin_vel_z` 管身体。

### 3.4 `_reward_ang_vel_xy`

方式：

```text
penalty = base_ang_vel_x^2 + base_ang_vel_y^2
```

作用：

- 惩罚 roll/pitch 方向的机身角速度，降低侧翻、前后俯仰震荡。

关系：

- 与 `orientation` 类似都关注姿态稳定，但当前 Go2 默认未启用 `orientation`，因此 `ang_vel_xy` 是主要的姿态动态约束。
- 与 `tracking_ang_vel` 互补：允许 yaw 转动，但抑制 roll/pitch 摆动。
- 与 `collision`、`correct_base_height` 共同降低摔倒风险。

### 3.5 `_reward_orientation`

方式：

```text
penalty = projected_gravity_x^2 + projected_gravity_y^2
```

`projected_gravity` 是重力方向投影到机身坐标系后的向量。机身越水平，x/y 分量越接近 0。

作用：

- 惩罚机身非水平姿态，鼓励身体保持平稳。

当前状态：

- 基础配置中为 `-0.0`，当前 Go2 默认 `scales` 没有启用它。

关系：

- 比 `ang_vel_xy` 更像“姿态位置误差”，`ang_vel_xy` 是“姿态速度误差”。
- 若在复杂地形上启用过强，可能压制身体顺应坡面、台阶和落脚点的自然姿态变化。
- 与 `upright` 都使用 `projected_gravity`，但 `upright` 专为翻身恢复设计。

### 3.6 `_reward_base_height`

方式：

1. 找出接触中的脚。
2. 计算接触脚平均位置。
3. 用 `projected_gravity` 方向估计机身相对接触脚的高度。
4. 返回：

```text
penalty = (base_height - base_height_target)^2
```

只有存在脚接触时才惩罚。

作用：

- 惩罚机身高度偏离目标高度。
- 这种版本以接触脚为参照，对局部地形高度有一定适应性。

当前状态：

- 当前 Go2 默认未启用 `base_height`，启用的是 `_reward_correct_base_height`。

关系：

- 与 `correct_base_height` 目标相同，但测量方式不同。
- `base_height` 更依赖脚接触状态，`correct_base_height` 更依赖高度扫描点估计地面。
- 若二者同时启用，容易重复惩罚机身高度，需要小心调权重。

### 3.7 `_reward_correct_base_height`

方式：

1. 通过 `_get_base_height` 估计机身高度。
2. 若 `measure_heights=True`，使用机身附近高度扫描点估计地面高度。
3. 返回：

```text
penalty = (base_height - base_height_target)^2
```

当前 Go2 默认 `base_height_target = 0.38`。

作用：

- 约束身体保持合理高度，防止趴低、塌陷、重心过低或异常跳高。

关系：

- 与 `lin_vel_z` 配合完成竖直稳定：一个约束高度，一个约束高度变化速度。
- 与 `feet_regulation` 配合：身体高度合理后，脚部高度估计才更有意义。
- 与 `tracking_lin_vel` 存在张力：高速追踪可能诱导身体高度下降，本项后期通过课程增强到 10 倍来纠偏。
- 与 `dof_pos_limits`、`hip_to_default` 一起防止策略用极端关节姿态维持速度。

### 3.8 `_reward_torques`

方式：

```text
penalty = sum(torque_i^2)
```

作用：

- 惩罚大力矩输出，鼓励省力、平滑、可迁移的动作。

关系：

- 与 `dof_power` 都是能耗类约束，但 `torques` 只看力矩幅值，`dof_power` 看力矩与关节速度的乘积。
- 与速度追踪正奖励冲突：追踪越激进，越可能需要大力矩。
- 与真机迁移强相关：过大力矩可能导致电机发热、打滑、冲击。

### 3.9 `_reward_dof_vel`

方式：

```text
penalty = sum(dof_vel_i^2)
```

作用：

- 惩罚关节速度，减少机械动作过快。

当前状态：

- 基础配置为 `-0.0`，当前 Go2 默认未启用。

关系：

- 与 `dof_acc`、`action_rate`、`action_smoothness` 同属平滑性约束。
- 若启用过强，可能限制快速摆腿，影响高速移动和跨障。

### 3.10 `_reward_dof_acc`

方式：

```text
penalty = sum(((last_dof_vel - dof_vel) / dt)^2)
```

作用：

- 惩罚关节加速度，减少动作突变和高频振荡。

关系：

- 与 `action_rate`、`action_smoothness` 共同抑制控制高频噪声。
- 比 `action_rate` 更接近真实机械状态，因为它直接看关节速度变化。
- 与 `feet_regulation` 有一定张力：脚部快速摆动可能产生较大关节加速度。

### 3.11 `_reward_action_rate`

方式：

```text
penalty = sum((last_action - action)^2)
```

作用：

- 惩罚相邻策略输出变化，鼓励动作连续。

关系：

- 与 `action_smoothness` 都约束动作序列，但本项是一阶差分。
- 与 `dof_acc` 互补：一个看策略输出，一个看物理关节状态。
- 对 sim2real 很重要，可降低真实执行中的抖动和延迟敏感性。

### 3.12 `_reward_action_smoothness`

方式：

```text
penalty = sum((action_t - 2 * action_{t-1} + action_{t-2})^2)
```

作用：

- 惩罚动作二阶差分，鼓励动作变化趋势平滑，而不仅仅是相邻帧接近。

关系：

- 比 `action_rate` 更关注“加加速度式”的动作突变。
- 与 `randomize_action_delay` 配合，有助于训练对执行延迟更鲁棒的策略。
- 过强会限制快速纠偏，可能降低复杂地形反应速度。

### 3.13 `_reward_collision`

方式：

```text
penalty = count(norm(contact_force on penalized bodies) > 0.1)
```

Go2 默认惩罚接触部位为 `thigh` 和 `calf`。

作用：

- 惩罚大腿、小腿等非脚部碰撞地面或障碍。
- 鼓励机器人用脚接触，而不是拖腿、磕腿、蹭障碍。

关系：

- 与 `feet_regulation`、`dof_pos_limits`、`hip_to_default` 共同塑造安全步态。
- 与 `tracking_lin_vel` 可能冲突：为了追踪速度硬冲障碍会导致碰撞惩罚。
- 与 `termination` 不同：`collision` 是软惩罚，`termination` 是摔倒或非法接触后的 episode 终止惩罚。

### 3.14 `_reward_termination`

方式：

```text
penalty = reset_buf & ~time_out_buf
```

只有非超时导致的 reset 才算终止惩罚。

当前状态：

- 基础配置有 `termination = -0.0`。
- 当前 Go2 默认 `scales` 未启用 `termination`。
- 但 `check_termination` 仍会因 base 接触等条件触发 reset。

关系：

- 与 `collision`、`orientation`、`correct_base_height` 都服务于安全性。
- 如果启用，通常用于强化“不要摔倒”的信号。
- 项目当前更依赖环境 reset 本身和其他软惩罚，而不是显式终止惩罚。

### 3.15 `_reward_dof_pos_limits`

方式：

```text
penalty = sum(amount outside softened joint position limits)
```

Go2 默认 `soft_dof_pos_limit = 0.9`，即使用 URDF 关节范围中心附近 90% 作为软限制区间。

作用：

- 惩罚关节位置接近或超过软限制，避免极端姿态。

关系：

- 与 `hip_to_default`、`similar_to_default` 都约束关节姿态，但本项只在接近限制时强烈生效。
- 与速度追踪、越障能力存在冲突：某些动作可能需要更大关节幅度。
- 对真机安全很关键，防止策略利用仿真中可行但硬件危险的姿态。

### 3.16 `_reward_dof_vel_limits`

方式：

```text
penalty = sum(clip(abs(dof_vel) - dof_vel_limit * soft_dof_vel_limit, 0, 1))
```

作用：

- 惩罚超过软速度限制的关节速度。

当前状态：

- 基础配置为 `0.0`，当前 Go2 默认未启用。

关系：

- 与 `dof_vel` 不同，本项只惩罚超过限制的部分。
- 可作为硬件保护项，但启用过强可能影响快速摆腿。

### 3.17 `_reward_torque_limits`

方式：

```text
penalty = sum(clip(abs(torque) - torque_limit * soft_torque_limit, min=0))
```

作用：

- 惩罚接近或超过电机力矩软限制。

当前状态：

- 基础配置为 `0.0`，当前 Go2 默认未启用。

关系：

- 与 `torques` 不同，本项只在超限附近生效。
- 可作为硬安全边界，`torques` 则是全局节能正则。

### 3.18 `_reward_feet_air_time`

方式：

1. 记录每只脚离地时间。
2. 当脚第一次重新接触地面时奖励：

```text
reward = sum((feet_air_time - 0.5) * first_contact)
```

3. 当 xy 指令速度很小时不奖励。

作用：

- 鼓励更长步幅和明显摆腿，常用于形成跑/走步态。

当前状态：

- 基础配置中为正奖励 `1.0`，当前 Go2 默认未启用。

关系：

- 与 `tracking_lin_vel` 通常协同，能帮助速度更高的步态形成。
- 与 `feet_regulation` 的方向不同：`feet_air_time` 奖励长时间离地，`feet_regulation` 在脚低且水平速度大时惩罚。
- 若启用不当，可能诱导夸张跳跃或高抬腿；项目当前更偏向用 `feet_regulation` 控制脚部质量。

### 3.19 `_reward_stumble`

方式：

```text
penalty = any(horizontal_foot_contact_force > 5 * vertical_foot_contact_force)
```

作用：

- 惩罚脚撞到竖直表面或发生绊脚。

当前状态：

- 基础配置中写的是 `feet_stumble = -0.0`，函数名是 `_reward_stumble`。
- 因为 scale 为 0，它不会参与；若未来把 `feet_stumble` 改成非零，会找不到 `_reward_feet_stumble`，需要改名为 `stumble` 或补对应函数。

关系：

- 与 `collision` 都处理接触异常，但 `stumble` 专注脚部水平撞击，`collision` 专注非脚部碰撞。
- 与复杂地形通过能力可能冲突，过强会让策略过于保守。

### 3.20 `_reward_stand_still`

方式：

```text
penalty = sum(abs(dof_pos - default_dof_pos)) * (norm(command_xy) < 0.1)
```

作用：

- 当目标线速度接近 0 时，鼓励机器人回到默认站立姿态。

当前状态：

- 基础配置为 `-0.0`，当前 Go2 默认未启用。

关系：

- 与 `hip_to_default`、`similar_to_default` 类似，但只在零速度命令下生效。
- 若启用，可改善静止时抖腿和姿态漂移。
- 与转向命令要小心区分：当前代码只看 xy 线速度，不看 yaw 指令。

### 3.21 `_reward_feet_contact_forces`

方式：

```text
penalty = sum(clip(norm(foot_contact_force) - max_contact_force, min=0))
```

Go2 默认 `max_contact_force = 147`，约等于 15 kg 机身重量乘重力加速度。

作用：

- 惩罚过大的脚端冲击力，减少跺脚和落脚冲击。

当前状态：

- 当前 Go2 默认注释中说明尝试过 `feet_contact_forces = -1.0`，但“no effect, remove”，因此未启用。

关系：

- 与 `feet_regulation`、`action_smoothness` 都能降低脚端冲击。
- 与高速/越障动作冲突明显，阈值和权重需要很谨慎。

### 3.22 `_reward_dof_power`

方式：

```text
power_i = torque_i * dof_vel_i
penalty = sum(abs(power_i))
```

作用：

- 惩罚机械功率消耗，鼓励节能动作。

关系：

- 与 `torques` 互补：大力矩但关节慢、力矩小但关节快，二者关注点不同。
- 与 `tracking_lin_vel`、`tracking_ang_vel` 有自然冲突，因为快速运动需要能量。
- 对真机表现重要，可减少暴力动作、打滑和发热。

### 3.23 `_reward_feet_regulation`

方式：

1. 估计机身高度 `base_height`。
2. 计算每只脚相对地面的高度 `feet_height`。
3. 计算脚端 xy 速度平方，并用脚高度进行指数衰减：

```text
penalty = sum(feet_xy_vel^2 * exp(-feet_height / (0.025 * base_height_target)))
```

脚越低，水平速度越大，惩罚越强；脚抬高后，同样水平速度惩罚会变小。

作用：

- 鼓励摆腿时先抬脚再水平移动，减少拖脚、扫地、绊倒。
- 这是项目从 CTS 奖励体系中保留的重要脚部正则。

关系：

- 与 `collision` 协同减少小腿/大腿碰撞。
- 与 `tracking_lin_vel` 有张力：高速移动需要脚快，但本项要求脚低时不能快。
- 与 `correct_base_height` 相关：机身高度估计影响脚高度估计。
- 与 `feet_air_time` 不同，它不直接奖励长腾空，而是惩罚低空水平扫腿。

### 3.24 `_reward_similar_to_default`

方式：

```text
penalty = sum(abs(dof_pos - default_dof_pos))
```

作用：

- 鼓励所有关节保持接近默认姿态。

当前状态：

- 当前 Go2 默认未启用，仅在配置注释中作为可能替代 `hip_to_default` 的实验项。

关系：

- 比 `hip_to_default` 更强，因为它约束全部 12 个关节。
- 有助于真机迁移和自然姿态，但可能明显限制爬楼、跨障、高速步态。
- 与 `dof_pos_limits` 不同，它在正常范围内也持续施加姿态偏好。

### 3.25 `_reward_upright`

方式：

```text
reward_or_penalty_raw = (-1 - projected_gravity_z) / 2
```

在正常直立时，机身坐标系下的重力投影 z 分量通常接近 `-1`，该值接近 0；翻倒时会偏离。

作用：

- 用于 `turn_over` 翻身训练阶段，鼓励机器人从侧躺/倒置恢复到直立。

当前状态：

- `turn_over_scales.upright = 1.0`，但默认 `init_state.turn_over = False`，因此默认训练不启用。

关系：

- 与 `orientation` 都使用 `projected_gravity`，但 `upright` 只在翻身逻辑中有意义。
- 当 `turn_over=True` 且 `abs(roll) > turn_over_roll_threshold` 时，奖励汇总会切换到 `turn_over_scales`。
- 翻正后再回到普通 locomotion 奖励体系。

### 3.26 `_reward_legs_distance`

方式：

1. 把四只脚位置转到机身坐标系。
2. 计算前腿左右间距、后腿左右间距。
3. 若小于 `min_legs_distance`，返回平方惩罚：

```text
penalty = clamp(min_dist - front_dy, min=0)^2
        + clamp(min_dist - rear_dy, min=0)^2
```

作用：

- 惩罚左右腿距离过近，避免交叉腿和腿间碰撞。

当前状态：

- 当前 Go2 默认注释掉了 `legs_distance = -1.5`。
- 更新日志中记录：该项通过 RoboGauge 指标验证没有提升，因此删除。

关系：

- 与 `hip_to_default` 目标相近，都是避免腿部姿态异常。
- `legs_distance` 直接看脚间距，`hip_to_default` 间接约束髋关节。
- 对爬楼梯可能有副作用，因为某些地形上脚位需要更灵活。

### 3.27 `_reward_hip_to_default`

方式：

```text
hip_indices = [0, 3, 6, 9]
penalty = sum(abs(hip_pos - default_hip_pos))
```

只约束四个 hip joint。

作用：

- 防止策略为了追踪速度或爬障，把左右髋关节张得过开、收得过窄或形成不适合真机的侧向姿态。
- 当前 Go2 默认启用，系数 `-0.05`。

关系：

- 是 `similar_to_default` 的温和版本，只管髋关节，不强行限制大腿和小腿摆动。
- 与 `legs_distance` 目标类似，但比直接脚距惩罚更柔和。
- 与 `tracking_lin_vel`、复杂地形通过能力存在张力；项目注释说明 CTS 奖励容易训练出脚距过近，真机表现差，因此加入该项改善迁移。

### 3.28 `_reward_x_command_hip_regular`

方式：

```text
x_command_ratio = abs(command_x) / norm(command_x_y_yaw)
penalty_raw = abs(FL_hip + FR_hip) + abs(RL_hip + RR_hip)
penalty = penalty_raw * x_command_ratio
```

作用：

- 当 x 方向速度指令占主导时，鼓励左右髋关节对称。

当前状态：

- 默认 `go2_config.py` 未启用。
- `go2_config_fast_flat_move.py` 中启用，系数 `-0.5`，用于高速平地移动实验。

关系：

- 比 `hip_to_default` 更有条件性：只在 x 方向命令明显时强调左右对称。
- 与高速前进协同，可减少高速直线时的横向髋关节不对称。
- 公式中 `norm(command_xyz)` 若非常接近 0，理论上有除零风险；在启用时最好确认零命令分布下是否需要加 epsilon。

## 4. 奖励项之间的结构关系

### 4.1 主目标：速度追踪

核心正奖励是：

- `tracking_lin_vel`
- `tracking_ang_vel`

这两项定义任务目标：按给定 x/y/yaw 指令移动。其他大多数奖励都是为了限制策略用不稳定、不节能、不安全的方式拿到追踪奖励。

### 4.2 稳定性约束

主要稳定项：

- `lin_vel_z`
- `ang_vel_xy`
- `correct_base_height`
- 可选 `orientation`
- 可选 `termination`

它们共同约束身体不要乱跳、乱滚、趴低或摔倒。其中 `lin_vel_z` 通过课程后期降为 0，说明项目认为复杂地形后期不能过分压制竖直运动；`correct_base_height` 后期增强，则负责持续维持合理身体高度。

### 4.3 动作平滑与能耗

主要项：

- `torques`
- `dof_power`
- `dof_acc`
- `action_rate`
- `action_smoothness`
- 可选 `dof_vel`
- 可选 `dof_vel_limits`
- 可选 `torque_limits`

这些项把策略从“仿真里能跑”推向“真实机器能执行”。它们共同限制大力矩、高功率、高频抖动和动作突变。

### 4.4 接触与脚部质量

主要项：

- `collision`
- `feet_regulation`
- 可选 `feet_air_time`
- 可选 `feet_contact_forces`
- 可选 `stumble`

当前默认更强调 `collision` 和 `feet_regulation`：既避免非脚部碰撞，又避免脚低空扫地。`feet_air_time` 这种传统步态塑形奖励未启用，说明项目并不直接奖励长腾空，而是让步态从速度追踪和脚部正则中自然形成。

### 4.5 姿态先验与真机迁移

主要项：

- `dof_pos_limits`
- `hip_to_default`
- 可选 `similar_to_default`
- 可选 `legs_distance`
- 可选 `x_command_hip_regular`

这些项处理一个典型 sim2real 问题：仿真策略可能利用极端腿型、过窄脚距或不自然髋关节姿态来通过地形，但真机表现差。项目最终默认选择 `hip_to_default`，而不是更强的 `similar_to_default` 或 `legs_distance`，体现了“约束髋关节，但保留腿部运动自由度”的折中。

## 5. 实验配置差异

除了当前注册默认配置 `go2_config.py`，仓库还有几个 Go2 配置文件用于实验。

### 5.1 `go2_config_vanilla.py`

奖励主体系与默认 Go2 基本一致，但：

- `dynamic_sigma = None`
- `heading_command = True`
- episode 长度 20 秒
- command resampling 10 秒

含义：速度追踪奖励使用固定 `sigma=0.25`，不会按地形和速度放宽。

### 5.2 `go2_config_vanilla_with_dynamic_cmd.py`

奖励主体系与 vanilla 基本一致，但：

- `heading_command = False`
- `dynamic_resample_commands = True`
- command resampling 5 秒
- `dynamic_sigma = None`

含义：命令采样更动态，但追踪奖励仍用固定 sigma。

### 5.3 `go2_config_fast_flat_move.py`

高速平地实验配置：

- `terrain.mesh_type = 'plane'`
- `base_height_target = 0.33`
- `tracking_lin_vel = 2.0`
- 启用 `x_command_hip_regular = -0.5`
- command range curriculum 会逐步扩大 x 方向速度上限
- 虽然配置了 `dynamic_sigma`，但平地环境没有 `terrain_ids`，`_get_dynamic_sigma` 会退回默认 `tracking_sigma = 0.25`

含义：更强调高速 x 方向移动，因此加倍线速度追踪奖励，并加入 x 速度场景下的髋关节对称约束。

## 6. 设计结论

当前 Go2 默认奖励设计可以概括为：

```text
任务目标：
  跟踪 x/y 线速度和 yaw 角速度

稳定底座：
  控制竖直速度、roll/pitch 角速度和机身高度

真机可迁移：
  限制力矩、功率、关节加速度、动作变化和髋关节偏离

复杂地形：
  用 dynamic_sigma 放松困难地形的速度追踪刚性
  用 feet_regulation 减少低空扫腿
  用 collision 避免非脚部碰撞

训练课程：
  早期压竖直速度，后期强化机身高度
```

这套奖励不是单纯追求速度，而是在速度、稳定、脚部质量、能耗、关节安全和真机迁移之间做折中。最有项目特色的部分是：

1. `dynamic_sigma`：困难地形和高速命令下放宽追踪误差，允许策略优先保证通过率。
2. `correct_base_height` 课程增强：后期强力纠正机身高度，减少趴低和重心偏移。
3. `feet_regulation`：惩罚低空高速扫腿，比直接奖励腾空时间更稳健。
4. `hip_to_default`：针对 CTS 奖励容易产生过窄脚距、真机迁移差的问题，只约束髋关节，保留其他腿部自由度。
